# Обновление рекомендаций — 18.10.2026

Реализованы три изменения: отсев технических названий, подгрузка новых карточек и локальные иллюстрации категорий. Контракт запросов, ответов и примеры обновлены в [api-contract.md](api-contract.md).

## Качество названий

Выбран вариант A: пропускать POI без допустимого исходного названия. [Аудит до очистки](name-quality-audit.json) нашёл одну такую запись среди 602 в SQLite и снимке карты: `osm_node_4209560711`, `Т34-85`, то есть 0,1661%. Это значение действительно записано в исходном теге OSM `name` у объекта `historic=tank`; оно не возникло из подстановки `ref` или ID. Вариант A теряет одну запись и позволяет сохранить названия остальных мест без выдуманного переименования.

Из 1069 объектов исходного кеша 467 уже пропускались из-за отсутствия `name` и языковых вариантов. Новая проверка оставляет 601 допустимое место: SQLite и снимок карты очищены, исходный кеш сохранён. Название выбирается из `name`, `name:ru`, `name:kk`, `name:en`. Перед очисткой создана резервная копия `backend/data/poi-before-name-cleanup.sqlite3` с 602 строками; каталог игнорируется Git.

Правило отсекает названия без букв, явные OSM/ref/id и короткие обозначения с несколькими числовыми группами. Оно намеренно сохраняет неоднозначные бренды `Z-1` и `А8`. Проверка применяется при сборе, построении снимка и чтении старых записей для рекомендаций: подходящий языковой тег может заменить техническое имя, иначе POI не попадёт к Gemini. Машинный `id` остаётся для связей и подгрузки.

## Подгрузка

Каждый ответ содержит не более трёх карточек и `has_more`. Для продолжения frontend повторяет зафиксированные параметры поиска, передаёт ID всех показанных мест в `exclude_ids` и добавляет новые карточки. Новый поиск сбрасывает выдачу. Исключения применяются до ранжирования и ограничения кандидатов; повторяющиеся и неизвестные ID не мешают поиску.

`has_more` определяется дополнительным поиском оставшихся POI, без второго вызова Gemini. Это учитывает и выборки больше 12 кандидатов, и fallback с одной карточкой при коротком бюджете. Уже загруженные карточки остаются при ошибке продолжения; повторный запрос доступен. Ограничения `exclude_ids`: до 10 000 строк, каждая 1–128 символов после обрезки пробелов; неверные значения получают обычный HTTP 422.

## Иллюстрации

Поле `image_url` допускает `null`; текущий backend подставляет локальный путь `/assets/icons/...` по категории. Frontend загружает SVG со своего origin и обозначает их как иллюстрации категорий. Это статические значки, а не реальные фотографии мест; внешние фотосервисы и дополнительные API не подключаются.

## Границы изменения

Фильтр названий — эвристика, а не подтверждение смысловой корректности каждого имени. Изображения не подтверждают внешний вид места. Эти изменения также не доказывают точность произвольного текста Gemini; ограничения генерации и шаблонные объяснения продолжают действовать. Качество живого ответа Gemini в рамках этих изменений отдельно не проверялось.

- В настоящем Edge проверены frontend и backend с рабочей SQLite: сначала 3 + 3 новые карточки, сохранение исходных параметров при редактировании формы, сохранение карточек после HTTP 500 и успешный повтор. Поиск дошёл до конца: 94 разных места за 62 страницы, включая прежний fallback с одной карточкой и предупреждением о бюджете. Кнопка затем скрылась.

Изменения оставлены в рабочем дереве локальной `main`; новый коммит и push в рамках этой задачи не выполнялись. Для просмотра после запуска приложения нужно перезапустить backend и обновить страницу без кеша (`Ctrl+F5`).
