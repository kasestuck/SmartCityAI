## Критерии жюри (по убыванию веса) → чем закрываем

| Критерий | Что показываем |
|---|---|
| 1. Релевантность | Реальные POI рядом с точкой, подбор по времени и категории; ИИ объясняет только найденное |
| 2. Контекст и адаптивность | Расстояние, время на дорогу и визит, категории, точка старта, предупреждение о превышении бюджета; статус по расписанию OSM. Фильтры особых потребностей пока mock |
| 3. Качество объяснений | «Почему» + «что делать» в каждой карточке; честные пометки «по данным OSM», «нет данных» |
| 4. UX демо | Быстрые идеи в один клик, карта со всеми местами, понятные состояния ошибок |
| 5. Креативность | 3 языка интерфейса и 2 языка API, сведения OSM о доступности, слой «вокруг меня», погода и новости, мини-маршрут (`TODO`) |
| 6. Этика и приватность | Координаты не храним, источники пояснений различаем, статус работы — только по расписанию OSM; раскрываем внешние сервисы |
| 7. Завершённость | Этот комплект + README + контракт API |

## Порядок работ

1. **Уже проверено на API:** Gemini, `language: "kk"`, короткий бюджет с `budget_warning`; статус по расписанию реализован с `null` при неизвестных данных. Сохранить эти проверки при объединении.
2. **Вместе:** поднять бек и фронт, прогнать 5 сценариев, заполнить столбец «Факт» в `03-test-scenarios.md`.
3. Скриншоты по каждому сценарию → в презентацию.
4. Слайды по `05-presentation.md` → PDF.
5. Видео по `06-demo-video.md` → YouTube (доступ по ссылке).
6. Проверить локальное объединение `FRONT` и `BACK` в `main` и README; после ревью и разрешения команды опубликовать и сдать ссылку.
