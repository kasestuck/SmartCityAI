# Предложение к контракту API: особые потребности, язык ответа, все места для карты

Статус: **частично реализовано; оставшиеся изменения — предложение.** Текущий контракт —
[`api-contract.md`](api-contract.md). API уже принимает `language: "ru" | "kk"` и возвращает
`wheelchair` / `accessibility` из OSM. Поле `accessibility` в запросе, язык `en` и `GET /api/poi`
ещё не реализованы; примеры с ними ниже описывают будущий контракт.

Зачем: критерии кейса НИЦ Smart City — «контекстуальность и адаптивность (учёт явных ограничений)»,
стретч-цели «доступность» и «мультиязычность», а также «указывать степень уверенности».

## Что уже сделано на фронте

- В форме AI-гида блок «Особые потребности»: `wheelchair` (передвигаюсь на коляске),
  `low_mobility` (трудно ходить далеко), `quiet` (нужны тихие места без толпы). Необязательный.
- Интерфейс на трёх языках: русский, казахский, английский (`js/i18n.js`).
- Карточка показывает доступность только по данным OSM, без догадок:
  «Доступно для коляски · по данным OSM» / «Частично…» / «Недоступно…» /
  «Нет данных о доступности — уточните на месте».
- `BACKEND_SUPPORTS_LANGUAGE = true`: RU/KZ отправляют `ru`/`kk`, EN отправляет `ru`
  с явной пометкой о русском ответе. Названия и описания POI остаются в исходном языке OSM.
- `BACKEND_SUPPORTS_ACCESSIBILITY = false`: поле запроса не отправляется в живой API,
  поскольку `extra="forbid"` отклоняет его с 422. Демонстрация фильтров доступна только в mock-режиме.

## 1. Запрос: реализованный язык и предлагаемая доступность

```json
{
  "latitude": 51.09,
  "longitude": 71.42,
  "query": "Хочу пообедать",
  "duration_minutes": 60,
  "transport": "walking",
  "categories": ["restaurant"],
  "accessibility": ["wheelchair"],
  "language": "kk"
}
```

| Поле | Тип | Правило |
|---|---|---|
| `accessibility` | array of strings | **Предложение, сейчас не принимается API.** Необязательное. Значения: `wheelchair`, `low_mobility`, `quiet`. Неизвестные — ошибка валидации 422. Пустой массив = поле не передано |
| `language` | string | Реализовано: необязательное `ru` (по умолчанию) или `kk`. `en` — предложение; сейчас 422. Задаёт язык пояснений, действий и системных примечаний |

## 2. Ответ: уже реализованные поля рекомендации

| Поле | Тип | Смысл |
|---|---|---|
| `wheelchair` | `"yes" \| "limited" \| "no" \| null` | Значение тега OSM `wheelchair` из базы как есть; `null`, если тега нет |

Поле есть всегда (как `opening_hours`). Уже реализованное поле ответа `accessibility` повторяет
`wheelchair`; оно не означает поддержку одноимённого поля запроса и не подтверждает доступность маршрута.

## 3. Предлагаемое поведение фильтров и расширение языков

**`wheelchair`**
- Исключать места с `wheelchair=no`.
- В ранжировании поднимать `yes`, затем `limited`, затем места без тега.
- В промпт Gemini передавать значение тега и требование: «если данных нет — прямо скажи, что доступность не подтверждена».
- Шаблонное объяснение (без Gemini) тоже должно сообщать уровень уверенности.

**`low_mobility`**
- Считать пешую скорость ниже: например, 50 м/мин вместо 75. Радиус и время дороги уменьшатся сами.
- В объяснении упоминать близость и, если есть данные, наличие скамеек.

**`quiet`**
- Поднимать в ранжировании `park`, `museum`, `viewpoint`.
- Gemini — не обещать тишину, а писать «обычно спокойнее», если это следует из категории.

**`language`**
- Уже реализовано: инструкция Gemini и шаблонные тексты на `ru` / `kk`.
- Предложение: добавить `en` в API и английские шаблоны.
- Названия и описания мест остаются как в OSM.

## 4. Приватность предлагаемого поля запроса

Особые потребности — чувствительные данные о здоровье. Поэтому:
- не логировать и не сохранять поле `accessibility`, как и координаты;
- в Gemini передавать как ограничения подбора («нужен доступ без ступенек»), без формулировок о диагнозах;
- в интерфейсе выбор необязательный, текст под блоком: «Отметки нигде не сохраняются».

## 5. Данные: честно о покрытии

В OpenStreetMap тег `wheelchair` в Астане заполнен редко. Проверка 18.10.2026: в радиусе 4 км от ЭКСПО
среди кафе, ресторанов, музеев, парков и площадок тег есть только у двух объектов. Поэтому главная
ценность фичи — **честность**: не выдавать место за доступное без данных.

Это стоит показать в презентации как ограничение и план развития. Возможный шаг — обратная связь
пользователей («здесь есть пандус») с модерацией.

## 6. Приёмочные сценарии для предлагаемого расширения

| Вход | Ожидаемый ответ |
|---|---|
| `accessibility: ["wheelchair"]`, рядом есть место с `wheelchair=yes` | Это место первым, в `reason` — «по данным OSM вход доступен для коляски» |
| `accessibility: ["wheelchair"]`, тегов рядом нет | Места с `wheelchair: null`, в `reason` — «доступность не подтверждена, уточните на месте» |
| `accessibility: ["low_mobility"]`, 60 мин | Только близкие места; дальние (>1 км) не попадают |
| `language: "en"` | `reason` и `suggested_action` на английском |
| `accessibility: ["unknown"]` | 422 `VALIDATION_ERROR` |

Реализованный `language: "kk"` проверен живым запросом 18.10.2026: три ответа Gemini без fallback;
см. `live_check_language_kk` в [demo-results.json](demo-results.json). Сценарии таблицы выше остаются будущими требованиями.

## 7. Предложение: все места для карты, `GET /api/poi`

Экран «Карта» показывает слой «все места» с вкладками «Вся карта» и «Вокруг» (радиус 1,5 км от точки
отправления). Пока эндпоинта нет, фронт берёт снимок OSM `data/poi-astana.json`. Снимок собран скриптом
`tools/build_poi_snapshot.py` по тем же правилам, что `collect_poi`: 602 места. Когда эндпоинт появится,
во фронте нужно включить `BACKEND_SUPPORTS_POI = true` в `js/config.js`.

```
GET /api/poi?limit=1000
GET /api/poi?latitude=51.09&longitude=71.42&radius_meters=1500&categories=cafe,park&limit=200
```

```json
{"places": [{"id": "osm_node_12990081501", "name": "Discovery Coffee", "latitude": 51.0906, "longitude": 71.4260, "category": "cafe"}]}
```

- Без ИИ, только выборка из базы; поля как у рекомендации, без `reason` и `suggested_action`.
- `latitude` / `longitude` / `radius_meters` необязательны: без них — весь город. Ограничения: `radius_meters` ≤ 5000, `limit` ≤ 1000.
- Координаты пользователя в запросе — те же правила приватности: не логировать, не хранить.
- Ошибки — в формате контракта (`VALIDATION_ERROR` и т. д.).

Зачем это жюри: наглядно видно «R» в RAG — система выбрала 3 места из десятков вокруг.
