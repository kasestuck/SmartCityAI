# Контракт API Smart City AI

Версия проекта контракта: 1. Основа — `BACKEND_SPEC_Smart_City.pdf`, страницы 2–3. Состав JSON-полей сохранён. Уточнения поведения, отсутствующие в исходном документе, явно обозначены ниже и подлежат согласованию перед реализацией.

## Общие правила

- Базовый путь: `/api`.
- Запросы и ответы: JSON, UTF-8.
- Координаты: WGS84, расстояния: метры, длительность: минуты.
- В MVP поддерживается только `walking`.
- От 0 до 3 рекомендаций. Каждая рекомендация соответствует реальной записи в базе POI.
- Клиент получает названия, координаты, описания, часы и источники из базы. Gemini формирует только `reason` и `suggested_action`.
- `distance_meters` — расстояние по прямой по формуле Haversine. Это не длина пешего маршрута.
- `estimated_duration_minutes` — приблизительный бюджет на дорогу к одному месту и посещение; это предлагаемое уточнение. Три рекомендации являются альтернативами, а не готовым последовательным маршрутом.

## Проверка работоспособности

`GET /api/health`

HTTP 200:

```json
{"status":"ok"}
```

Предлагаемое уточнение: endpoint проверяет, что приложение запущено и база доступна для чтения. Наличие ключа и доступность Gemini не обязательны; запрос к Gemini при health-проверке не выполняется. При недоступности базы — HTTP 500 с `INTERNAL_ERROR`.

## Получение рекомендаций

`POST /api/recommendations`

Заголовок: `Content-Type: application/json`.

```json
{
  "latitude": 51.09,
  "longitude": 71.42,
  "query": "Хочу кофе и прогулку",
  "duration_minutes": 60,
  "transport": "walking",
  "categories": ["cafe", "park"]
}
```

| Поле | Тип | Обязательное | Правило |
| --- | --- | --- | --- |
| `latitude` | number | да | Конечное число от -90 до 90 включительно |
| `longitude` | number | да | Конечное число от -180 до 180 включительно |
| `query` | string | да | 1–500 символов; предлагаемое уточнение: после удаления пробелов по краям |
| `duration_minutes` | integer | да | От 15 до 240 включительно |
| `transport` | string | да | Только `walking` |
| `categories` | array of strings | нет | Фильтр категорий |

Предлагаемые уточнения валидации: булевы значения не принимаются вместо чисел; неизвестные поля отклоняются; нецелая длительность отклоняется. Некорректный JSON обрабатывается как ошибка валидации.

Предлагаемые категории MVP: `cafe`, `restaurant`, `park`, `museum`, `attraction`, `viewpoint`, `playground`. Отсутствующий `categories` и `[]` означают отсутствие явного фильтра. Категории в списке объединяются через «ИЛИ». Неизвестные строки не вызывают ошибку схемы, но совпадений в базе для них нет; запрос только с неизвестными категориями возвращает пустой результат. Для одного POI хранится одна основная нормализованная категория.

HTTP 200:

```json
{
  "recommendations": [
    {
      "id": "osm_node_12345",
      "name": "Пример места",
      "latitude": 51.095,
      "longitude": 71.425,
      "category": "cafe",
      "description": "Описание из POI",
      "reason": "Подходит для короткого отдыха",
      "distance_meters": 650,
      "estimated_duration_minutes": 30,
      "suggested_action": "Выпить кофе",
      "opening_hours": null,
      "source": "OpenStreetMap"
    }
  ]
}
```

Это пример формы из технического ТЗ, а не сведения о реальном месте. Числа расстояния и времени иллюстрируют формат; их нельзя использовать как контрольные значения расчёта.

| Поле рекомендации | Тип | Смысл |
| --- | --- | --- |
| `id` | string | Стабильный идентификатор `osm_<type>_<id>` |
| `name` | string | Название из POI |
| `latitude`, `longitude` | number | Координаты из POI |
| `category` | string | Нормализованная категория |
| `description` | string или null | Исходное описание; null при отсутствии |
| `reason` | string | Короткое объяснение выбора, от модели либо шаблона |
| `distance_meters` | number | Конечное неотрицательное расстояние по прямой |
| `estimated_duration_minutes` | integer | Положительная приблизительная длительность |
| `suggested_action` | string | Действие, согласованное с категорией и известными данными |
| `opening_hours` | string или null | Исходное значение OSM, без обещания «открыто сейчас» |
| `source` | string | `OpenStreetMap` для данных сборщика MVP |

Если подходящих POI нет, в том числе при пустой базе или запросе далеко от Астаны:

```json
{"recommendations":[]}
```

HTTP 200 при пустой выдаче и при работе с шаблонными объяснениями. API не создаёт места для заполнения трёх карточек. Все ключи рекомендации присутствуют, отсутствующие описание и часы представлены как `null`.

## Ошибки

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Некорректные параметры запроса"
  }
}
```

| HTTP | `error.code` | Условие |
| --- | --- | --- |
| 422 | `VALIDATION_ERROR` | Предлагаемый единый статус для ошибок схемы, координат, JSON и параметров |
| 400 | `VALIDATION_ERROR` | Допускается исходным ТЗ; отдельный случай в MVP пока не требуется |
| 429 | `RATE_LIMITED` | Ограничение запросов к нашему API, если включено |
| 500 | `INTERNAL_ERROR` | Ошибка базы или неожиданная внутренняя ошибка |
| 503 | `AI_UNAVAILABLE` | Резерв контракта для случая без возможности fallback |

Недоступность Gemini, отсутствие ключа, его rate limit или некорректный ответ сами по себе не превращают запрос в 429/503: MVP возвращает найденные POI с шаблонными пояснениями. Прямое ограничение запросов к нашему API — отдельная ситуация. Внешняя квота модели не должна ломать демо.

Ответы об ошибках не содержат traceback, ключи, исходное тело запроса или точную пользовательскую геолокацию.

## Интеграция с интерфейсом

- Frontend использует этот JSON без переименования полей. Тестовые карточки разрешены в `mock-data.js` с явной пометкой mock и не загружаются в рабочую SQLite.
- Разрешённые CORS origins задаются настройками backend для адреса frontend. Предлагаемый локальный origin — `http://localhost:5173`; фактический порт можно изменить в конфигурации.
- Клиент сообщает: места и факты взяты из OpenStreetMap; объяснения и действия генерируются моделью либо составляются по шаблону.
- В интерфейсе нужна атрибуция «© OpenStreetMap contributors» со ссылкой на [условия OpenStreetMap и лицензию ODbL](https://www.openstreetmap.org/copyright).
- Интерфейс обозначает время и расстояние как оценки и не выводит «открыто сейчас» на основании непроверенной строки `opening_hours`.
- Поля контракта меняются только согласованно между backend и frontend. Примерная локальная база API после реализации: `http://localhost:8000`.
