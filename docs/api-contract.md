# Контракт API Smart City AI

Версия контракта: 1, дополнения от 18.10.2026. Основа — `BACKEND_SPEC_Smart_City.pdf`, страницы 2–3. Существующие поля сохранены; новые параметры и поля описаны ниже.

## Общие правила

- Базовый путь: `/api`.
- Запросы и ответы: JSON, UTF-8.
- Координаты: WGS84, расстояния: метры, длительность: минуты.
- В MVP поддерживается только `walking`.
- От 0 до 3 рекомендаций за один ответ. Следующие порции запрашиваются через `exclude_ids`; каждая рекомендация соответствует реальной записи в базе POI.
- Клиент получает названия, координаты, описания, часы и источники из базы. Gemini формирует только `reason` и `suggested_action`.
- `distance_meters` — расстояние по прямой по формуле Haversine. Это не длина пешего маршрута.
- `estimated_duration_minutes` — приблизительный бюджет на дорогу к одному месту и посещение; это предлагаемое уточнение. Три рекомендации являются альтернативами, а не готовым последовательным маршрутом.
- `generated_by` указывает происхождение текста `reason` и `suggested_action`. Время и расстояние рассчитывает backend; это оценки, а не поля из OSM или ответы Gemini.
- Backend использует исходные теги OSM при текстовом ранжировании. `query_context` показывает параметры пользовательского запроса, которые участвовали в поиске.

## Проверка работоспособности

`GET /api/health`

HTTP 200:

```json
{"status":"ok"}
```

Предлагаемое уточнение: endpoint проверяет, что приложение запущено и база доступна для чтения. Наличие ключа и доступность Gemini не обязательны; запрос к Gemini при health-проверке не выполняется. При недоступности базы — HTTP 500 с `INTERNAL_ERROR`.

## Получение рекомендаций

`POST /api/recommendations`

Заголовок: `Content-Type: application/json`.

```json
{
  "latitude": 51.09,
  "longitude": 71.42,
  "query": "Хочу кофе и прогулку",
  "duration_minutes": 60,
  "transport": "walking",
  "categories": ["cafe", "park"],
  "language": "ru",
  "exclude_ids": []
}
```

| Поле | Тип | Обязательное | Правило |
| --- | --- | --- | --- |
| `latitude` | number | да | Конечное число от -90 до 90 включительно |
| `longitude` | number | да | Конечное число от -180 до 180 включительно |
| `query` | string | да | 1–500 символов; предлагаемое уточнение: после удаления пробелов по краям |
| `duration_minutes` | integer | да | От 15 до 240 включительно |
| `transport` | string | да | Только `walking` |
| `categories` | array of strings | нет | Фильтр категорий |
| `language` | string | нет | `ru` (по умолчанию) или `kk`; язык объяснений Gemini, шаблонов и служебных примечаний. Другие значения — 422 |
| `exclude_ids` | array of strings | нет | По умолчанию `[]`; до 10 000 элементов. Каждый ID после удаления пробелов по краям содержит 1–128 символов. Исключает уже показанные места |

Предлагаемые уточнения валидации: булевы значения не принимаются вместо чисел; неизвестные поля отклоняются; нецелая длительность отклоняется. Некорректный JSON обрабатывается как ошибка валидации. Для `exclude_ids` значения `null`, не массив, нестроковые элементы, пустые после обрезки строки и превышение указанных ограничений дают HTTP 422 с существующим `VALIDATION_ERROR`. Повторяющиеся и неизвестные ID допускаются: повторное исключение не меняет результат, неизвестный ID игнорируется.

Предлагаемые категории MVP: `cafe`, `restaurant`, `park`, `museum`, `attraction`, `viewpoint`, `playground`. Отсутствующий `categories` и `[]` означают отсутствие явного фильтра. Категории в списке объединяются через «ИЛИ». Неизвестные строки не вызывают ошибку схемы, но совпадений в базе для них нет; запрос только с неизвестными категориями возвращает пустой результат. Для одного POI хранится одна основная нормализованная категория.

HTTP 200:

```json
{
  "recommendations": [
    {
      "id": "osm_node_12345",
      "name": "Пример места",
      "latitude": 51.095,
      "longitude": 71.425,
      "category": "cafe",
      "description": "Описание из POI",
      "reason": "Подходит для короткого отдыха",
      "distance_meters": 650,
      "estimated_duration_minutes": 30,
      "suggested_action": "Выпить кофе",
      "opening_hours": null,
      "source": "OpenStreetMap",
      "status_note": "Часы работы не подтверждены",
      "generated_by": "gemini",
      "is_open_now": null,
      "budget_warning": null,
      "wheelchair": null,
      "accessibility": null,
      "phone": null,
      "website": null,
      "wikidata": null,
      "image_url": "/assets/icons/lc-coffee.svg"
    }
  ],
  "query_context": {
    "latitude": 51.09,
    "longitude": 71.42,
    "categories": ["cafe", "park"],
    "duration_minutes": 60,
    "transport": "walking"
  },
  "language": "ru",
  "has_more": true
}
```

Это пример формы из технического ТЗ, а не сведения о реальном месте. Числа расстояния и времени иллюстрируют формат; их нельзя использовать как контрольные значения расчёта.

| Поле рекомендации | Тип | Смысл |
| --- | --- | --- |
| `id` | string | Стабильный машинный идентификатор `osm_<type>_<id>` для связей и `exclude_ids`; не отображаемое название |
| `name` | string | Допустимое исходное название из POI: `name`, затем `name:ru`, `name:kk`, `name:en` |
| `latitude`, `longitude` | number | Координаты из POI |
| `category` | string | Нормализованная категория |
| `description` | string или null | Исходное описание; null при отсутствии |
| `reason` | string | Короткое объяснение выбора, от модели либо шаблона |
| `distance_meters` | number | Конечное неотрицательное расстояние по прямой |
| `estimated_duration_minutes` | integer | Положительная приблизительная длительность |
| `suggested_action` | string | Действие, согласованное с категорией и известными данными |
| `opening_hours` | string или null | Исходное значение OSM, без обещания «открыто сейчас» |
| `source` | string | `OpenStreetMap` для данных сборщика MVP |
| `status_note` | string или null | При неизвестном статусе: «Часы работы не подтверждены». При вычисленном: «По расписанию OpenStreetMap; фактические часы работы уточните перед визитом». Для `kk` — казахский текст |
| `generated_by` | string | `gemini` или `fallback_template` — происхождение `reason` и `suggested_action` |
| `is_open_now` | boolean или null | `true`/`false` — результат проверки расписания OSM на момент запроса в часовом поясе Астаны; `null` — определить не удалось. Это не подтверждение фактической работы места |
| `budget_warning` | string или null | «Превышает ваш бюджет на X минут», когда оценка посещения превышает запрос; иначе `null`. Для `kk`: «Уақыт бюджетіңізден X минутқа асады» |
| `wheelchair` | string или null | Исходное значение тега OSM; обычно `yes`, `no`, `limited`. Другие значения сохраняются без переинтерпретации |
| `accessibility` | string или null | Точная копия `wheelchair`, не отдельная проверка доступности |
| `phone` | string или null | `phone` из OSM, при отсутствии — `contact:phone` |
| `website` | string или null | `website` из OSM, при отсутствии — `contact:website` |
| `wikidata` | string или null | Исходный тег OSM, обычно ID вида `Q…`; дополнительных запросов в Wikidata нет |
| `image_url` | string или null | Необязательное поле схемы, по умолчанию `null`. В текущих ответах backend — путь к локальной SVG-иконке категории, например `/assets/icons/lc-coffee.svg` |

Дополнительные поля карточки (`is_open_now`, `budget_warning`, `wheelchair`, `accessibility`, `phone`, `website`, `wikidata`, `image_url`) nullable и имеют значение по умолчанию `null`. В HTTP-ответе они присутствуют всегда. На верхнем уровне `language` возвращает выбранное значение (`ru` по умолчанию), в том числе при пустом результате и fallback. Названия и другие факты POI не переводятся; качество языка Gemini не гарантируется автоматически.

### Имена и иллюстрации

Сборщик использует первое допустимое значение из `name`, `name:ru`, `name:kk`, `name:en`. `ref` и машинный ID не подставляются вместо названия. Пропускаются пустые значения, названия без букв, явные ID OSM/ref и короткие обозначения с несколькими числовыми группами, например `Т34-85`. Это консервативная эвристика, а не смысловая проверка всех названий; неоднозначные короткие бренды вроде `Z-1` и `А8` сохраняются. При чтении старой базы та же проверка выполняется до ранжирования и передачи кандидатов Gemini: допустимый альтернативный языковой тег заменяет техническое название, а запись без такого названия исключается.

`image_url` обозначает категорию, а не вид конкретного места. Пути `/assets/icons/...` разрешаются относительно origin frontend, без добавления базового URL API. Иконки поставляются с frontend; внешний сервис фотографий и отдельный API для картинок не используются. Интерфейс обозначает такую картинку как иллюстрацию категории; при `null` может показать обычную иконку категории.

| Категория | `image_url` |
| --- | --- |
| `cafe` | `/assets/icons/lc-coffee.svg` |
| `restaurant` | `/assets/icons/lc-utensils.svg` |
| `park` | `/assets/icons/lc-trees.svg` |
| `museum` | `/assets/icons/lc-landmark.svg` |
| `attraction` | `/assets/icons/lc-camera.svg` |
| `viewpoint` | `/assets/icons/lc-binoculars.svg` |
| `playground` | `/assets/icons/lc-baby.svg` |

Для неизвестной категории при построении карточки предусмотрена `/assets/icons/lc-map-pin.svg`; текущий поиск ограничен поддерживаемыми категориями.

### Подгрузка рекомендаций

| Поле ответа | Тип | Смысл |
| --- | --- | --- |
| `recommendations` | array | От 0 до 3 новых карточек за один запрос |
| `query_context` | object | Применённые параметры поиска в описанном ниже формате |
| `language` | string | `ru` или `kk`, включая пустой результат и шаблонные объяснения |
| `has_more` | boolean | Всегда присутствует. Есть ли ещё допустимые места после исключения всех ID запроса и карточек текущего ответа; для пустого результата — `false` |

Первый запрос не передаёт `exclude_ids` либо передаёт `[]`. Для «Показать ещё» клиент повторяет исходные параметры и перечисляет в `exclude_ids` ID **всех** уже показанных карточек. Например, после приведённого выше ответа:

```json
{
  "latitude": 51.09,
  "longitude": 71.42,
  "query": "Хочу кофе и прогулку",
  "duration_minutes": 60,
  "transport": "walking",
  "categories": ["cafe", "park"],
  "language": "ru",
  "exclude_ids": ["osm_node_12345"]
}
```

Исключения применяются до ранжирования и ограничения списка кандидатов 12 местами. Поэтому продолжение может находить места за пределами первой выборки кандидатов. После формирования ответа backend повторно выполняет только поиск POI с объединением входных `exclude_ids` и ID возвращённых карточек, чтобы вычислить `has_more`; дополнительного запроса к Gemini для этой проверки нет. Число карточек само по себе не определяет наличие продолжения: fallback при коротком бюджете может вернуть одну карточку и `has_more: true`, если остаётся ещё подходящее место. Предупреждение `budget_warning` при этом сохраняется.

Backend не хранит сессию или номер страницы. Клиент фиксирует параметры начатого поиска и добавляет следующие карточки к существующим без дублей. Новый поиск с изменёнными параметрами начинает отдельную выдачу с пустым списком исключений. При `has_more: false` клиент прекращает подгрузку. Если данные базы между запросами изменились, следующая порция может оказаться пустой.

### Часы, бюджет и контекст

Часы разбирает библиотека `opening-hours-py`. Используется текущий серверный момент времени с переводом в `Asia/Almaty`. Отсутствующая, некорректная или неоднозначная строка, предупреждение парсера и правила `PH`/`SH`/восхода/заката без необходимого контекста дают `is_open_now: null`. Закрытые по расписанию места остаются в выдаче. Frontend показывает этот статус только вместе с оговоркой об источнике и актуальности.

Если обычный поиск не находит ни одного места, укладывающегося в бюджет, он рассматривает подходящие категории в пределах расстояния `duration_minutes × 75 / 1.3` метров по прямой. Возвращается одно место с минимальной оценкой времени (затем расстоянием и ID при равенстве). Время посещения категорий не сокращается; превышение показывается в `budget_warning`. Например, кафе прямо в точке запроса при бюджете 15 минут имеет оценку 20 минут и предупреждение о превышении на 5 минут. Если подходящих мест нет и в этом радиусе, результат остаётся пустым. Обычное ранжирование сохраняется.

`query_context` присутствует даже при пустом списке рекомендаций. `latitude` и `longitude` в нём округлены до трёх знаков только для отображения; поиск использует точные координаты запроса. `categories` показывает фактически применённые поддерживаемые категории: без повторов, в алфавитном порядке; неизвестные значения исходного фильтра исключаются. `[]` означает отсутствие явного фильтра либо отсутствие поддерживаемых категорий в заданном фильтре; во втором случае выдача пуста. `duration_minutes` и `transport` отражают параметры, принятые backend.

При `opening_hours: null` Gemini получает явный запрет утверждать, что место открыто или закрыто сейчас. Очевидные заявления о текущем статусе в `reason` или `suggested_action` сервер отклоняет и заменяет шаблонным текстом с `generated_by: "fallback_template"`. Исходная строка часов OSM сама по себе не подтверждает текущий статус.

Если подходящих POI нет, в том числе при пустой базе или запросе далеко от Астаны:

```json
{"recommendations":[],"query_context":{"latitude":51.09,"longitude":71.42,"categories":["cafe","park"],"duration_minutes":60,"transport":"walking"},"language":"ru","has_more":false}
```

HTTP 200 при пустой выдаче и при работе с шаблонными объяснениями. API не создаёт места для заполнения трёх карточек. Все ключи рекомендации присутствуют, отсутствующие сведения представлены как `null`.

## Ошибки

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Некорректные параметры запроса"
  }
}
```

| HTTP | `error.code` | Условие |
| --- | --- | --- |
| 422 | `VALIDATION_ERROR` | Предлагаемый единый статус для ошибок схемы, координат, JSON и параметров |
| 400 | `VALIDATION_ERROR` | Допускается исходным ТЗ; отдельный случай в MVP пока не требуется |
| 429 | `RATE_LIMITED` | Ограничение запросов к нашему API, если включено |
| 500 | `INTERNAL_ERROR` | Ошибка базы или неожиданная внутренняя ошибка |
| 503 | `AI_UNAVAILABLE` | Резерв контракта для случая без возможности fallback |

Недоступность Gemini, отсутствие ключа, его rate limit или некорректный ответ сами по себе не превращают запрос в 429/503: MVP возвращает найденные POI с шаблонными пояснениями. Прямое ограничение запросов к нашему API — отдельная ситуация. Внешняя квота модели не должна ломать демо.

Ответы об ошибках не содержат traceback, ключи, исходное тело запроса или точную пользовательскую геолокацию.

## Интеграция с интерфейсом

- Frontend использует этот JSON без переименования полей. Тестовые карточки разрешены в `mock-data.js` с явной пометкой mock и не загружаются в рабочую SQLite.
- Разрешённые CORS origins задаются настройками backend для адреса frontend. Предлагаемый локальный origin — `http://localhost:5173`; фактический порт можно изменить в конфигурации.
- Клиент сообщает: места и факты взяты из OpenStreetMap; объяснения и действия генерируются моделью либо составляются по шаблону.
- В интерфейсе нужна атрибуция «© OpenStreetMap contributors» со ссылкой на [условия OpenStreetMap и лицензию ODbL](https://www.openstreetmap.org/copyright).
- Интерфейс обозначает время и расстояние как оценки и не выводит «открыто сейчас» на основании непроверенной строки `opening_hours`.
- Интерфейс отображает `budget_warning`, если оно заполнено; для статуса использует `is_open_now` вместе с `status_note`. `null` нельзя трактовать как «закрыто» или «открыто».
- Кнопка «Показать ещё» использует `exclude_ids` и `has_more`, добавляет карточки к текущей выдаче и блокируется на время запроса. Ошибка подгрузки сохраняет уже полученные карточки и позволяет повторить запрос.
- Поля контракта меняются только согласованно между backend и frontend. Локальный адрес API задаётся в `js/config.js`; в текущем окружении — `http://localhost:8001`.
