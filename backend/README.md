# Запуск бэкенда Smart City AI

Части 2–5: FastAPI, SQLite, автоматический сбор POI Астаны из OpenStreetMap, геопоиск, ранжирование и Gemini RAG с шаблонными объяснениями при недоступности модели. `GET /api/health` проверяет чтение таблицы POI. `POST /api/recommendations` выдаёт от нуля до трёх реальных мест из базы.

Нужен Python 3.11 или новее. Все команды ниже выполняются из корня репозитория. Для первого сбора данных нужен интернет. Gemini необязателен: без ключа API работает с реальными POI и шаблонными пояснениями. Сеть в автоматических тестах не используется.

## Windows PowerShell

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.txt
if (-not (Test-Path -LiteralPath backend/.env)) { Copy-Item backend/.env.example backend/.env }
.\.venv\Scripts\python.exe -m backend.scripts.collect_poi
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000 --no-access-log
```

Активация окружения не обязательна; команды используют его Python напрямую. `.env` копируется один раз при первом запуске. Если установлен только Python из окружения Codex, команду создания `.venv` можно выполнить этим интерпретатором вместо `py -3`.

## Linux и macOS

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-dev.txt
[ -f backend/.env ] || cp backend/.env.example backend/.env
.venv/bin/python -m backend.scripts.collect_poi
.venv/bin/python -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000 --no-access-log
```

Для запуска без инструментов разработки достаточно `backend/requirements.txt`. `backend/requirements-lock.txt` фиксирует проверенное окружение вместе с инструментами тестирования; для воспроизведения этих версий установите его вместо `requirements-dev.txt`.

## Сбор и обновление данных

```powershell
# Обычный запуск: свежий кеш или запрос Overpass.
.\.venv\Scripts\python.exe -m backend.scripts.collect_poi

# Обновить данные из сети независимо от кеша.
.\.venv\Scripts\python.exe -m backend.scripts.collect_poi --force

# Также поддерживается прямой запуск файла.
.\.venv\Scripts\python.exe backend/scripts/collect_poi.py
```

Сборщик запрашивает node/way/relation семи категорий в прямоугольнике Астаны. Сохраняются OSM type/id, имя, координаты, категория, доступные описание/часы, исходные теги, источник и UTC-дата получения. Для way/relation используется центр геометрии. Объекты без имени или корректных координат пропускаются. Названия берутся из `name`, затем `name:ru`, `name:kk`, `name:en`. Отсутствующие поля остаются `null`.

Повторный запуск обновляет записи по OSM type/id без дублей. Кеш содержит исходный ответ и дату; чтение кеша не меняет дату исходных данных. Просроченный или повреждённый кеш не считается свежим. При ошибке сети без пригодного кеша команда завершается ненулевым кодом, существующие POI сохраняются. Есть таймауты, ограниченные повторы и задержки для временных ошибок Overpass. Ошибочный или частичный ответ сервиса не становится успешным кешем.

Категории: `cafe`, `restaurant`, `park`, `museum`, `attraction`, `viewpoint`, `playground`. Для пересекающихся тегов применяется первый подходящий признак в этом порядке. Сбор выполняется отдельно от пользовательского запроса; API не скачивает весь город при каждом обращении.

База и кеш не коммитятся. В рабочую базу не добавляются mock-данные. Источник: [© OpenStreetMap contributors, ODbL](https://www.openstreetmap.org/copyright).

## Подключение Gemini

В локальном `backend/.env` задайте `GEMINI_API_KEY` из [Google AI Studio](https://aistudio.google.com/apikey). Не отправляйте ключ в чат, frontend или репозиторий. Модель задаётся `GEMINI_MODEL`; пример использует `gemini-3.8-flash`. Доступ к модели и квота зависят от вашего аккаунта.

Gemini получает запрос, бюджет времени и shortlist найденных POI. Точные координаты пользователя отдельно не передаются; свободный текст запроса всё равно может содержать сведения, которые ввёл сам пользователь. В форме AI-гида уже есть предупреждение о передаче текста запроса внешнему AI-сервису и просьба не вводить личные данные.

Модель формирует только `id`, `reason` и `suggested_action`. Сервер проверяет id по shortlist; названия, координаты, описания, часы и источник берёт из базы. Неизвестные и повторные id отбрасываются. Без ключа, при таймауте, ошибке квоты или некорректном ответе возвращаются реальные кандидаты с шаблонными объяснениями и HTTP 200. При пустой выдаче модель не вызывается.

## Проверка API

- Health: [http://localhost:8000/api/health](http://localhost:8000/api/health).
- Swagger UI: [http://localhost:8000/docs](http://localhost:8000/docs).
- OpenAPI: [http://localhost:8000/openapi.json](http://localhost:8000/openapi.json).
- Общий [контракт API](../docs/api-contract.md).

В другом окне PowerShell:

```powershell
Invoke-RestMethod http://localhost:8000/api/health

$body = @{
    latitude = 51.09
    longitude = 71.42
    query = "Хочу кофе и прогулку"
    duration_minutes = 60
    transport = "walking"
    categories = @("cafe", "park")
} | ConvertTo-Json

Invoke-RestMethod -Uri http://localhost:8000/api/recommendations -Method Post -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
```

Ожидается health `{"status":"ok"}`. После сбора POI рекомендации содержат до трёх карточек с реальными названиями, объяснением и действием. При пустой базе, неизвестных категориях или отсутствии подходящих мест поблизости нормальный результат — `{"recommendations":[]}`.

## Настройки

`backend/.env` читается независимо от текущей рабочей папки. Переменные окружения процесса имеют приоритет над файлом.

| Настройка | По умолчанию | Назначение |
| --- | --- | --- |
| `DATABASE_PATH` | `data/poi.sqlite3` | Путь относительно `backend/`; абсолютный путь тоже допускается |
| `CORS_ORIGINS` | `["http://localhost:5173"]` | JSON-массив разрешённых origin интерфейса |
| `OVERPASS_URL` | `https://overpass-api.de/api/interpreter` | Endpoint сбора OSM |
| `OVERPASS_BBOX` | `[50.95,71.20,51.30,71.75]` | Южная, западная, северная, восточная границы |
| `OVERPASS_TIMEOUT_SECONDS` | `45` | Сетевой таймаут сборщика |
| `OVERPASS_ATTEMPTS` | `3` | Максимум попыток обращения |
| `OVERPASS_RETRY_DELAY_SECONDS` | `2` | Начальная задержка повтора |
| `POI_CACHE_PATH` | `cache/overpass.json` | Путь кеша относительно backend |
| `POI_CACHE_TTL_SECONDS` | `86400` | Срок свежести кеша, секунды |
| `GEMINI_API_KEY` | пусто | Необязательный секретный ключ |
| `GEMINI_MODEL` | `gemini-3.8-flash` | Имя модели без префикса `models/` |
| `GEMINI_TIMEOUT_SECONDS` | `8` | Таймаут отдельной сетевой операции Gemini |

SQLite и каталог данных создаются при старте приложения. Отдельный сервер БД и миграционные команды для первой схемы не требуются. Повторный запуск сохраняет существующие записи. При недоступной базе во время старта запуск завершается ошибкой; потеря базы после старта даёт JSON 500 на health и рекомендации. Изменения схемы в будущих частях потребуют отдельного решения о миграциях.

Соединения SQLite открываются на операцию и закрываются после commit/rollback. В health используется чтение существующего файла; отсутствующая база не создаётся заново во время этой проверки.

## Валидация и ошибки

Координаты должны быть конечными JSON-числами в допустимом диапазоне. Числовые строки и булевы значения не принимаются. Время — целое JSON-число 15–240; `60.0` тоже отклоняется. Запрос обрезается по краям, затем проверяется длина 1–500 символов. Лишние поля запрещены. `categories` можно пропустить или передать `[]`; `null` недопустим. `language` принимает `ru` (по умолчанию) или `kk`; `en` и поле запроса `accessibility` пока не поддерживаются.

Ошибки запроса имеют HTTP 422:

```json
{"error":{"code":"VALIDATION_ERROR","message":"Некорректные параметры запроса"}}
```

Ошибка SQLite или непредвиденное исключение имеют HTTP 500:

```json
{"error":{"code":"INTERNAL_ERROR","message":"Внутренняя ошибка сервера"}}
```

Для неизвестного URL и неверного метода используются HTTP 404 `NOT_FOUND` и 405 `METHOD_NOT_ALLOWED` с тем же JSON-конвертом. Коды 429 `RATE_LIMITED` и 503 `AI_UNAVAILABLE` зарезервированы контрактом; при сбое Gemini используется fallback с HTTP 200. Ограничитель частоты нашего API пока не подключён. Заголовки HTTP-ошибок, например `Allow` и `Retry-After`, сохраняются.

Внутренние сообщения исключений, тело запроса и пользовательские координаты не выдаются в ошибках и не записываются приложением в логи. Команды запуска отключают access log Uvicorn; при настройке внешнего прокси его логи нужно проверять отдельно.

## Проверки

Windows:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check backend
.\.venv\Scripts\python.exe -m pip check
```

Linux/macOS: замените `.\.venv\Scripts\python.exe` на `.venv/bin/python`.

Тесты используют временные SQLite и не изменяют рабочую базу. Проверяются схемы и ошибки, CORS, транзакции, нормализация OSM, кеш и повторы, геопоиск и время, неизвестные id модели, fallback и сквозной API. Внешний HTTP подменяется на границе транспорта. Настоящий сетевой сбор проверяется отдельно CLI-командой.

## Геопоиск и ограничения

SQL отбирает места по географическому прямоугольнику и явным категориям, Haversine уточняет расстояние по прямой. Категории запроса объединяются через «ИЛИ» и ограничивают выдачу жёстко. Намерения «кофе», «прогулка», «семья» и «турист» влияют на приоритет категорий, дополнительно учитываются слова в данных POI и близость. Shortlist содержит максимум 12 мест, ответ — максимум 3 альтернативы.

Время — оценка одного пути к одному месту и типового посещения. Используются скорость 75 м/мин и коэффициент 1,3 к прямому расстоянию. Бюджеты посещения: кафе 20, ресторан 45, парк 20, музей 45, достопримечательность 20, смотровая 10, площадка 20 минут. Сначала выбираются места в бюджете. Если таких нет, возможно одно подходящее близкое место в радиусе пешего подхода с полной оценкой времени и явным `budget_warning` о превышении; если нет и его, ответ пустой. Возвращаться к старту или проходить все три места этот расчёт не предполагает.

Реальная навигация, закрытые проходы, доступность с коляской и безопасность маршрута не проверяются. Прямоугольник сбора не является административной границей Астаны. Данные OSM могут быть неполными и устаревшими; ранее собранные, затем удалённые из OSM места автоматически из SQLite пока не удаляются. Часы передаются как исходная строка OSM. `is_open_now` рассчитывается по расписанию для `Asia/Almaty`; неизвестные, некорректные или неподдерживаемые правила дают `null`. `status_note` предлагает уточнить часы. Это не проверка фактической работы; закрытые по расписанию места не исключаются. Розетки, тишина, выставки и рейтинги не придумываются.

Проверка id защищает от вымышленных объектов, но не доказывает истинность каждой фразы генератора. Источник пояснений указан в `generated_by` (`gemini` или `fallback_template`); факты карточки — данные OSM. Ответ API также содержит `query_context` с применёнными параметрами и округлённой точкой. `wheelchair` и `accessibility` в ответе повторяют исходные сведения OSM, не гарантируя доступность; одноимённый фильтр запроса не реализован. Пользовательские запросы и история геолокации не сохраняются. Подробнее: [сценарии проверки](../docs/test-scenarios.md) и [ограничения](../docs/limitations.md).

Реализация опирается на официальную документацию [lifespan FastAPI](https://fastapi.tiangolo.com/advanced/events/), [обработки ошибок](https://fastapi.tiangolo.com/tutorial/handling-errors/), [CORS](https://fastapi.tiangolo.com/tutorial/cors/) и [строгой валидации Pydantic](https://docs.pydantic.dev/latest/concepts/strict_mode/).

Внешние API: [Overpass QL](https://wiki.openstreetmap.org/wiki/Overpass_API/Overpass_QL), [Gemini generateContent](https://ai.google.dev/api/generate-content), [структурированные ответы Gemini](https://ai.google.dev/gemini-api/docs/structured-output), [доступные модели](https://ai.google.dev/gemini-api/docs/models).
